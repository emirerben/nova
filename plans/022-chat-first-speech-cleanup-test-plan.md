# Test Plan

## Affected Pages/Routes

- `/plan` chat workspace - verify the boxed speech-cleanup decision and all analysis states for Talking to camera and Narrated.
- `POST /creation-threads/{thread_id}/media` - verify video, embedded-audio, recorded narration, and uploaded narration trigger the correct current analysis.
- `POST /creation-threads/{thread_id}/actions` - verify cleanup choice and render start happen atomically and are revision/idempotency fenced.
- `GET /creation-threads/{thread_id}` - verify analysis progress and the active
  Job-generation cleanup receipt hydrate without exposing private source,
  transcript, timed-word, or CutPlan data; list summaries must not load it.
- Narrated render path - verify standalone narration can be analyzed before footage exists, but rendering stays blocked until at least one video clip is present.
- Ready result and embedded editor - verify applied, no-safe-change, declined, and cleanup-failed receipts agree with the rendered output.

## Key Interactions to Verify

- Attach equivalent speech media after unrelated chat messages and confirm the offer is identical.
- Observe Checking speech advance before any render Job exists while continuing to use the composer.
- Confirm analysis-only polling shows Checking speech and never re-labels the
  project or artifact as Rendering/building the first cut.
- Choose Clean up and create, then verify the produced video removes exactly the reviewed moments and keeps captions synchronized.
- Choose Keep speech and create, then verify the source speech remains unchanged and the Ready receipt says it was kept.
- Upload or record narration without video, review the cleanup result with no
  selected choice, then attach a video and choose without rerunning unchanged
  analysis.
- Continue from a no-findings result with the current analysis ID and no choice;
  verify the Job and Ready receipt say checked/no-change rather than declined.
- Replace, remove, or reorder the active narration source and verify the old choice disappears and a new check begins.
- Change only chat copy or visual metadata and verify the current analysis and choice remain valid.
- Retry only a retryable failed check. For a non-retryable source failure, replace
  or record narration; when otherwise renderable, explicitly create without cleanup
  and receive an unchecked-bypass receipt rather than a checked/declined claim.
- Retry a transient cleanup application failure against the same immutable snapshot;
  never rerun speech analysis after cleanup was accepted.
- Refresh or reopen the project in every state and verify the same current analysis and decision return.
- Double-submit each action and confirm exactly one decision and one render are created.

## Edge Cases

- No audio stream, silent audio, no detected speech, one cleanup moment, many moments, and an unsafe or empty CutPlan.
- Uploaded narration present but inactive; active narration missing or replaced at the same object path with a new generation.
- Multiple self-narrated clips where only the selected foreground speech spine may influence cleanup.
- Analysis commit succeeds but the process dies before queue publication; the Beat
  reconciler republishes the same row. Cover expired leases, killed-before-ack and
  killed-after-claim workers, and a stale worker that completes after reclaim.
- Replace an object at the same path after scheduling and prove both GCS and local
  storage consume only the generation pinned during media registration.
- Stale thread revision, stale analysis ID, cross-owner analysis ID, changed idempotency payload, and source change during submission.
- Provider timeout, analysis timeout, unreadable source, non-retryable failure, and unexpected programming exception.
- Old API response without speech-cleanup fields, old completed Job without a
  cleanup receipt, and a stale receipt from a non-active Job/generation.
- Every creator-facing Job projection (`/creation-threads`, generative jobs, and
  `/me`) strips `_speech_cleanup_internal.preflight_snapshot`; admin surfaces expose
  only the bounded operator receipt, never timed words or cut intervals.
- Slow or offline polling, project switch during polling, navigation away during
  submission, and component unmount during retry. Assert the prior fetch is aborted,
  one timer/request remains active, and late data cannot commit.
- 1440x900, 1280x720, 390x844, 375px wide, and 200% zoom; no overflow and actions stack correctly.
- Keyboard-only use, visible focus, 44px targets, one standalone polite live-region
  owner with no nested announcement, text-only state distinction, and reduced motion.
- Browser fixtures render the production `SpeechCleanupDecisionCard` (or intercept
  the real `/plan` API); no hand-built duplicate may satisfy the visual test.

## Critical Paths

- Talking to camera: attach speaking video -> automatic check -> findings -> Clean up and create -> render -> Ready receipt -> Play and editor.
- Narrated embedded audio: attach self-narrated video -> selected speech spine check -> explicit choice -> exact cleaned render.
- Narrated voiceover: record or upload narration -> automatic check -> attach supporting video if needed -> explicit choice -> exact cleaned narration-led render.
- Mixed-gap regression: run the synthetic #960 source through chat preflight, persistence, dispatch, and FFmpeg; verify the approved intervals and captions, and verify render performs no second transcription or detection.
- Recovery: retryable analysis failure -> Retry; non-retryable failure -> replace
  source or explicit unchecked bypass; cleanup application failure -> retry the same
  snapshot or explicit bypass, with no uncleaned Ready state.
- Rollout: dedicated speech-analysis worker consumes its queue, render workers remain unblocked, and production canary verifies the feature before each ramp stage.
