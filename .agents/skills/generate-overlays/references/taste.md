# Overlay taste guide

Emir can edit this guide or give examples to an agent. The following defaults are starting points, not observed personal preferences.

| Decision | Starting point | Feedback to collect |
| --- | --- | --- |
| Role | Explain or emphasize one concrete idea | Which graphic made the point clearer? |
| Density | A few separated overlays, with breathing room | Was the video too busy or too empty? |
| Shape | Clean cutout icons with readable silhouettes | Flat, outlined, hand drawn or dimensional? |
| Palette | Small palette drawn from the video | Preferred colors and colors to avoid |
| Timing | Start at the spoken trigger or verified visual event | Earlier anticipation or exact emphasis? |
| Motion | Existing subtle entrance and exit, only when useful | Preferred entrance and movement amount |
| Placement | Clear space outside moving faces, important objects and captions | Preferred corner or size |
| Text | Exact editable native text for numbers and labels | Font, weight, stroke and preferred scale |
| Logos | Supplied exact asset | Which approved logo version? |

## Accepted examples

Record the video context, trigger, image, placement, why it worked and any limits. Link only examples actually inspected.

## Rejected examples

Record the specific visible defect and the narrow correction. Keep the prior result available for comparison.

## Runtime calibration

In-app Style preferences are saved with the overlay draft and sent with each new plan. Editing this developer guide does not change the deployed app. Promote accepted changes through the reviewed runtime prompt and offline evidence cases.
