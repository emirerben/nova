# Troya: reusable research and physical iPhone verification

## Implemented

Chat can request source-backed explanations during initial creation or follow-up editing.
Public-topic Google Search runs before a caption writer receives bounded footage descriptions.
Provider grounding supplies citations; an institutional-domain filter excludes unsupported
hosts. A separate claim reviewer checks factual support and visual implications. Exact object
names, dates and identities need a visible label or an explicit current creator identification.
Museum membership alone cannot identify an object in a shot.

The server owns readable output windows, protected copy, clip order and audio. Research emits
ordinary text operations only. Source links, supporting facts, retrieval date, provider search
attribution and the bound timeline persist with each text element. Native Export → Sources
shows them and flags changed wording/timing/cuts for rechecking. Research uses the existing
reservation, settlement, deadline and unknown-outcome controls, including search-tool charges.

The earlier editorial-plan change preserves the visual hook, places the car second and
reserves room for explanations; this follow-up adds research without reordering the edit.

## Limits and release status

The phone used actual Troya analysis proxies, not full-resolution originals. The native UI
loaded the captured server draft in a separate QA app; this was not a signed-in production
chat-to-save journey. No production deployment or production media update was performed.

Institutional domains are a conservative registry plus government/academic domains. An
unknown institutional host may be refused until reviewed. Domain membership is not a truth
proof: provider grounding and the claim reviewer remain fallible. Unsupported or unidentifiable
objects require clarification, and research may take around a minute. Short existing cuts
without readable windows require a timing edit first; research does not silently extend them.
