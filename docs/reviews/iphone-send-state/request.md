# iPhone Send acceptance

Emir reported on 29 October 2026 that Send starts thinking while the submitted prompt stays in a locked composer and does not promptly appear in the feed.

The submitted text must appear promptly as a local pending message. The composer must clear without claiming server acceptance. Known rejection must recover text; unknown outcome must preserve the same request identity and payload for Retry. A newer draft must survive acknowledgement, rejection, navigation, editor-sheet use, backgrounding and relaunch. Retry/double tap/reconnect must not create duplicate prompts or jobs.

The bubble, submission status and Retry must remain visible above the composer with the keyboard open and closed. Incoming state must preserve a reader's earlier scroll position. A structured card answer that is refused after an uncertain attempt must keep its card-specific recovery instead of becoming composer text.

Scope is iPhone Send/message lifecycle. Preserve camera-roll navigation and other owners' preview, recovery and caption work. Physical-phone/production proof, planner policies and video export changes are outside this local delivery.
