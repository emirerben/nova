# Confirmed replacement order readers

This dependent reader increment keeps source and rejection producers inactive.
It does not claim to replay the original Cabildo conversation. Retained original
provider outputs are unavailable, so model misunderstanding versus adapter loss
remains unassigned.

A None answer cannot silently rewrite the entire historical order requirement.
For legacy compound orders, a future producer must show the complete remaining
sequence and obtain an explicit choice. The new proof binds that choice to its
saved server offer, canonical predecessor, rejection provenance, current source
identities, distinct occurrences and exact source/output intervals.

The canonical writer opt-in validates actual persisted question and answer events,
creator/thread ownership, current rejection and sources. It appends one brief
version atomically and preserves unrelated requirements and literal copy. Retry
with the same proof is idempotent. Ordinary later edits clear inherited proof.
No current planner call enables this opt-in.

Compatible readers accept the new server-only fields. Model ingress clears them.
Unset fields omit from legacy JSON. Provider/tool/mobile/OpenAPI contracts remain
byte identical. Every new strategy field is explicitly classified in the field
matrix, and unused proof paths stay out of legacy capability identity.

Preapproval runs the existing deterministic phone worker preflight and compiler
for a typed order, then verifies the full artifact against actor-owned sources.
Missing, stale or unsupported inputs stay unresolved. Legacy requests skip this
additional work before database reads. Final review reads the
actual current timeline and current database sources, discards cached typed-order
receipts, and verifies it again. A strategy field alone cannot produce success.

canonical PostgreSQL persistence, real preapproval/final-review callers, legacy
KRI-994 review, binding, prepared execution and field-matrix compatibility tests.
These counts overlap independent runs and must not be added together.

An independent review passed 99 pure/schema/compatibility tests and 31 PostgreSQL
persistence/caller tests. It found no blocking defect. Specialized Comment Sicko
was unavailable; comment review was manual.

The database was freshly initialized on localhost port 55439, named cabildo_test,
with existing migrations and transactional synthetic rows. No production database,
provider, external storage, or physical phone was used.

Negative controls cover wrong windows, wrong order, changed generation, invalid
proxy lineage, speed/freeze/photo timing, foreign creators/threads, stale offers,
repeated answers, missing authority, conflicting ordinary updates, cached false
met receipts and unrelated still-unlocated moments.

The real guided compiler includes photos and distinct moments. Separate retained
native evidence already demonstrated disjoint intervals from one source. These
checks are synthetic capability and reader evidence, not original-media export
acceptance or live-provider generalization.

Eight additional integration tests prove the production preflight route, current
phone receipts and selected Visuals readers without mocks. They retain negative
controls for missing inputs, conflicts, other writers and stale sources.

## Remaining activation boundary

Before producers activate, complete the actual planner offer/answer continuation,
freeze and recompile the displayed strategy through the ordinary native writer,
pass the opt-in canonical write in the existing turn transaction, preserve proof
through saved-editor operations, and verify the exact native publication artifact.
Any changed or unmapped sequence must ask again. No paid call or entire-library
reanalysis is needed for these deterministic invariants.

## Native Visuals identity integration follow-up

A new mixed video-plus-selected-photo test exposed a reader boundary defect before
activation. The actual worker compiler emits a Visuals row's raw UUID with lane
`asset`, while its canonical proof and current source fence use `asset-<UUID>` and
`visual:<UUID>`. Component fixtures had put the canonical ID directly into their
synthetic timeline and therefore missed the mismatch. This is a newly reproduced
reader integration bug, not an attribution of the original Cabildo model failure.

The verifier now maps only a checked canonical Visuals source slot to its native
UUID and requires the asset lane. It preserves canonical proof and source fences,
and never rewrites the compiled artifact. Existing path, generation, occurrence,
window, output timing, rate and photo-hold checks remain exact.

The real PostgreSQL/preflight/compiler mixed case failed before the fix and passes
after it. Wrong native IDs, paths, generations, lanes, canonical aliases in native
rows, and changed current source records remain rejected. Clip and video-only
behavior remains unchanged. Activation stays off.
