# KRI-999 timeline selection evidence

The creator reported that selecting a timeline item shows the preceding clip or
an instant before its text appears. The expected result is the selected item's
first available output frame, with playback paused.

## Case and result

The deterministic `selection-boundary` fixture has a red clip ending at 2.001 s,
a blue clip starting at 2.001 s, and text starting at 2.001 s. The fixture's
source-index colours are generated by `prepareFixtureSourcePreview` under
`-ui-testing-editor-color-cuts`.

Before the fix, commit `dea73f340` reproduced both failures through the real
native compositor. Both selections returned a scrub frame at 2.000 s.

```text
XCTAssertGreaterThanOrEqual failed: ("2.0") is less than ("2.001") - Selected clip shows the preceding frame
XCTAssertGreaterThanOrEqual failed: ("2.0") is less than ("2.001") - Selected text shows the preceding frame
```

The simulator UI test also failed both incoming-item pixel checks. The selected
second clip remained red with no visible text. This is a wrong-content control,
not just a timing-value assertion. The test samples the actual preview image
and requires blue pixels and visible white text for the incoming item.

After fix commit `4ea8017a2`, 39 fixture, interaction and real-compositor checks
and the one UI test passed on an iPhone 17 Pro simulator running iOS 26.5.
The UI test verified red without text initially, blue with text after selecting
the second clip, red without text after returning to the first clip, and blue
with text after selecting the text block. Playback stayed paused.

```text
Executed 39 tests, with 0 failures (0 unexpected) in 0.603 (0.616) seconds
Test Case '-[KriaUITests.NativeEditorInspectorUITests testTimelineSelectionShowsIncomingClipAndTextAtSubframeStart]' passed (10.581 seconds).
```

The retained local XCTest bundle is `/private/tmp/timeline-boundary-after.xcresult`.
Its four screenshots are named `Initial preceding clip`, `Selected incoming clip`,
`Return to preceding clip`, and `Selected incoming text`. The final screenshot
was inspected and shows the blue clip with selected text visible. These local
artifacts are not uploaded or represented as hosted CI artifacts.
