## Occurrence-specific speaker frame gap

Follow-up source review after the passing batch found a separate first-class editing defect: occurrence selection and viewport geometry are local, but drag/pinch/slider/preset/Full still mutate one global speaker frame. The repeated-speaker UI test asserted selection and movement without asserting unchanged peers. Do not infer independent speaker framing from that passing result.

A persistent occurrence-owned `speaker_frame_override` is implemented in source across authored slots, native/phone recipe compilation, AI operations, session editing and preview/export. Missing/inherit retains the global default; explicit full-panel is distinct from inheritance; custom uses existing validated frame geometry. Global controls continue to affect inheriting clips, while selecting one occurrence must change only that occurrence. Ordinary media transforms remain independent. Regression failure modes and required evidence are in [speaker occurrence framing](speaker-occurrence-failure-modes.md). New tests and implementation are unexecuted while the heavy lane is held; this gap is not closed by the earlier 436 passing tests. Existing background/window/color/focus controls now retain admission after valid split-origin Save and unstack, under their existing gates; explicit global removal no longer falls back to the old recipe background. These corrections also require execution.
