## Acceptance and scope

The retained incident record asks for five named moments from one long video, followed by a photo. The saved server-resolved strategy incorrectly associates the first video moment with the photo. A later structured None answer removes the interior intent, but the saved story and final review still describe the interior. Raw creator/extractor outputs are unavailable. These observations do not establish which model or adapter first made the association error.

This increment prepares compatible readers before new producers are enabled. The source-kind prompt and its version are unchanged. The live planner does not yet pass rejected selections into the strategy adapter. Existing projects keep their unconstrained behavior. KRI-1052 remains open.

Observable acceptance for these bounded contracts is:

- A declared video intent cannot accept a photo from resolver, vision, cache, filename, kept-label, description or transcript reassignment paths. A conflicting creator selection remains an explicit question, rather than being silently rebound.
- The authoritative question ID, category and selection sequence survive None folding and checked inventory planning. Superseded pins are not relabelled as creator rejections.
- Only revision-bound references can authorize removal of a derived story row. Identical retained caption copy survives. Missing or mixed references preserve the earlier outline explicitly as unresolved data and keep it out of the executable outline.
- The draft reply cannot retain the model's fulfillment promise after a checked rejection. The real writer preserves reconciliation metadata in its snapshot and pinned approval.
- Explicit omitted order moments produce honest partial receipts before approval and after worker compilation. The actual compiled cuts stay unchanged by omission receipts.
- Legacy JSON and approval readiness remain unchanged when the new fields are absent.

## Contracts and rollout

`ClipIntent.source_kind` is optional and omitted when unset. It constrains membership only. It does not prove that an interval depicts a named action. The existing moment-location path still owns that evidence.

`SelectionReconciliation` is optional, server-owned strategy metadata. Model ingress and the strategy adapter clear model-authored values. The checked selection boundary records rejection provenance before dropping intents. The adapter accepts that projection only through explicit server arguments. It can use checked story references, or quarantine unmapped prose without deleting it. Literal title/caption fields remain separate.

The preapproval checker and worker share one validated omission reader. A rejected order produces a skipped outcome without adding a seat, rerunning vision or changing source intervals. An `any_order` receipt does not turn an explicit skipped/unlocated moment into Done.

The field matrix enumerates dataclass children and assigns each new path explicitly. Legacy readiness excludes only the unused additive paths from its capability digest. A strategy using either contract includes those paths. Independent comparison against baseline code produced identical complete readiness results for default and unconstrained legacy strategies.

Deploy these readers to API and workers first. Then a separate increment may teach source-kind extraction, invalidate the old inventory prompt key, and pass authoritative rejection projections at the live planner boundary. No source prompt, feature flag or producer activation is included here. Rollback of that later producer must retain these readers for stored drafts and in-flight work. Returning workers to a pre-reader version while new-contract work is queued has not been established safe.

## Verification and limits

The fixtures are synthetic contract cases. They are not reconstructed raw provider outputs or original-media fulfillment evidence. Mock provider transport exercises the real clip-intent parser, normalization and selection application. Separate tests exercise the real strategy adapter, worker compilation, receipt composition, and JSON roundtrip. The database test freezes the already-prepared plan to test the actual writer and pinned approval boundary; it is not full conversation proof.

Positive and negative controls include the same scene confidently assigned to the wrong source kind, selected-photo conflicts and corrections, intentional repeated photos, unconstrained legacy records, exact quoted copy sharing the rejected phrase, mixed/unmapped story rows, wrong questions, repeated answers, invalid provenance, contradictory execution, and unrelated caption/include omissions.

The focused source/selection/receipt suites and existing neighboring suites passed. Actor-bound database selection and approval suites passed 66 checks. The new reader writer/approval persistence check passed. Independent review passed its combined 325 checks and reproduced the corrected conversion, ingress and schema-walk defects.

Known limits remain source constraint extraction quality, original first-source correction, original labels and order interpretation, full persisted conversation replay, live-provider generalization, native fulfillment and effective producer rollout.
